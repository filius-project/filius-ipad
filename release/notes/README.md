# Release Notes

`next.md` is the staging file for user-visible changes.

At release time:

1. Replace all placeholders and remove internal-only notes.
2. Copy or rename the file to `<marketing-version>.md`, using the exact Xcode marketing version (for example, `1.0.md`).
3. Add the release date and accepted commit/tag.
4. Move matching `CHANGELOG.md` entries from **Unreleased** to that version.
5. Start a new empty `next.md`.

Release notes describe observable changes, compatibility, known issues, and upgrade impact. They do not include internal branch names, credentials, private issue links, or unsupported claims about signing/App Store acceptance.
